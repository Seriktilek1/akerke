# Вместе — общий семейный бюджет

Версия для GitHub Pages + вашей базы Supabase. Два отдельных аккаунта, один бюджет.

## Что уже сделано

- Доходы, расходы, кредиты, рассрочки и долги, фильтр по супругу и месяцу.
- Банк, ставка, первоначальный взнос, платёж в месяц, срок и история выплат.
- Вход по почте и паролю. По умолчанию для операции выбран вошедший супруг.
- Хранение финансовых записей в базе, обновление каждые 10 секунд на открытой странице.
- Защита от перезаписи одновременно внесённых изменений. При конфликте загружается свежая версия; правку нужно повторить. Несохранённую копию можно скачать.
- JSON-копии и перенос старых данных.

## Сначала подключите базу (один раз)

1. Откройте https://supabase.com/dashboard и создайте проект в своём аккаунте. Пароль самой базы сохраните у себя: программе он не нужен. Выберите подходящий вам тариф и регион.
2. В проекте откройте **SQL Editor → New query**. Вставьте весь текст `setup.sql`, нажмите **Run**. Скрипт создаёт таблицы и ограничения доступа. Выполняйте в новом проекте один раз.
3. Откройте **Authentication → Users → Add user → Create new user**. Создайте свой аккаунт с почтой и паролем и затем отдельный аккаунт жены. Если предлагается **Auto Confirm User**, включите его для этих двух аккаунтов. Пароли вводите только в Supabase и на вашем сайте, не в коде и не в чате.
4. В настройках Authentication отключите публичную регистрацию новых пользователей (Allow new users to sign up). Сам сайт регистрации не предлагает; доступ к бюджету в любом случае даёт только таблица участников.
5. Откройте `connect-family.sql`, замените `YOUR_EMAIL@example.com` и `WIFE_EMAIL@example.com` на почту созданных аккаунтов. Выполните текст в SQL Editor один раз. Скрипт объединит аккаунты в одну семью. Повторный запуск не удаляет записи, а выдаёт ошибку.
6. В настройках проекта / окне **Connect** найдите **Project URL** и **Publishable key** (допустим также legacy **anon key**). Заполните две строки в `config.js`. **Secret key, service_role и пароль базы сюда не подходят.** Публичный ключ можно хранить в GitHub: доступ к записям ограничивается входом и политиками базы.

Пример config.js:

```js
window.WALLET_CONFIG = {
  url: "https://ВАШ_ПРОЕКТ.supabase.co",
  key: "ВАШ_ПУБЛИЧНЫЙ_КЛЮЧ"
};
```

## Опубликуйте на GitHub Pages

1. Создайте репозиторий GitHub.
2. Загрузите в корень **index.html**, **config.js** и **.nojekyll**. Не помещайте их внутрь ещё одной папки. SQL-файлы нужны только для настройки базы: публиковать их с вашими адресами почты не нужно.
3. Откройте **Settings → Pages → Deploy from a branch**, выберите **main**, папку **/(root)** и нажмите **Save**.
4. Откройте выданную GitHub ссылку на обоих телефонах. Каждый входит под своей почтой и паролем.
5. В настройках программы замените «Муж» и «Жена» на ваши имена и укажите начальный баланс.

Интерфейс GitHub / Supabase может немного отличаться по названиям разделов.

## Проверка на двух телефонах

- На первом телефоне добавьте пробный расход 100 ₸.
- На втором дождитесь 10 секунд или нажмите «Обновить»: запись должна появиться.
- Отредактируйте запись на втором, проверьте первый и удалите пробную операцию.
- В приватном окне без входа должны быть только поля авторизации, без сумм бюджета.
- Чужой аккаунт, не добавленный в `family_members`, не должен иметь доступа.
- Откройте форму одновременно на двух телефонах и сохраните по очереди. Второй должен показать конфликт; первая запись не должна пропасть. Повторите вторую правку на свежих данных.

## Перенос данных из старой версии

На старом сайте откройте **Настройки → Скачать копию**. На новом — **Настройки → Восстановить из файла**. Импорт заменяет общий бюджет ОБОИХ супругов. Для первой миграции импортируйте один подготовленный файл. Две копии с разных телефонов автоматически не объединяются: импорт второй заменит первую.

## Где хранятся данные

Финансовые записи — в таблице `family_wallets` вашего проекта Supabase. Связь аккаунтов с семьёй — в `family_members`. Аккаунты — в Supabase Auth. На GitHub находятся только файлы программы. В браузере хранится сессия входа; полный бюджет загружается в память страницы. При выходе экран бюджета скрывается. На чужом телефоне обязательно нажимайте «Выйти».

Оба супруга могут просматривать и изменять весь семейный бюджет, а поле «Кто» позволяет выбрать автора / участника операции. Публичной регистрации и самостоятельного присоединения к семье нет. Сменить забытый пароль можно через управление пользователями в вашем проекте Supabase.

Для изменений нужен интернет. Работа без сети с последующей автоматической отправкой не реализована. Если сохранение не подтверждено, программа не сообщает об успехе. При неоднозначной сетевой ошибке проверьте свежую историю перед повтором, чтобы не добавить дубль. Перед закрытием страницы скачайте предложенную несохранённую копию. Плановые уведомления при закрытом сайте не реализованы.

Проценты не начисляются автоматически; остаток и платёж вводятся по договору. После выплаты ближайшую дату меняйте в «Детали». Месячный итог — сумма заданных платежей активных кредитов и рассрочек.

## Файлы и проверка

- `index.html` — весь интерфейс, стили и логика.
- `config.js` — публичные параметры подключения.
- `setup.sql` — таблицы, RLS и серверная запись с проверкой версии.
- `connect-family.sql` — подключение двух заранее созданных аккаунтов.
- `tests.cjs` — локальные тесты сохранения, конфликтов, ошибки сети, защиты от устаревшего ответа и отсутствующей конфигурации. Запуск: `node tests.cjs`.
- `.nojekyll` — для статического размещения.

Сборка и Node.js для работы сайта не нужны. Модуль Supabase загружается через jsDelivr (версия 2.49.1). Нужен современный браузер и HTTPS.

Код подготовлен и локальные проверки выполнены. Живой вход, SQL-политики и обмен между двумя телефонами нужно проверить после создания вашего проекта: параметров действующей базы в комплекте нет.
